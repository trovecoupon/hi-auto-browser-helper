# Affiliate Discovery Browser Helper

Manifest V3 extension version **3.0.1** for Hi Auto Cloud. Browser Helper pairs with the Local Agent bridge at `http://127.0.0.1:8771`; the public UI is `https://hi-auto.vercel.app`. Run `npm install && npm run build`, then load this directory unpacked from `chrome://extensions`. Clicking the extension icon opens the Side Panel.

## User-triggered behavior

- Local app: probes the installed helper before creating a session. Pairing credentials travel in an in-memory extension event after the user's click; they are never placed in a URL or DOM attribute.
- One-click SERP job: after **Bắt đầu đào đối thủ**, the helper keeps exactly one active job and owns at most two temporary tabs, opens Valentin, validates Google context, and scans pages 1–5 sequentially. Every page stays open for a randomized 3.5–5.5 seconds, then requires a stable readable SERP DOM for 1.2 seconds and a durable idempotent ACK before navigation; page 5 also waits for domain aggregation before the controller tab is reused for sequential advertiser lookup. Only job-owned tabs are closed after terminal persistence. DOM waits are bounded; progress, stop, CAPTCHA, mismatch, timeout and disconnect states are written to Hi Auto. Organic results are never saved as paid ads.
- Resume/stop: the server owns durable job state, so reloading Hi Auto restores progress. Stop is checked between batches and before next-page navigation; saved batches remain intact.
- Advertiser handoff: high-confidence coupon catchers are searched sequentially in Ads Transparency. The helper waits up to ten seconds for visible semantic autocomplete options (including open shadow roots), excludes its own overlay, and selects only one exact registrable-domain match. A detached option is rescanned once and keyboard fallback is allowed only after the same unique match is reconfirmed. Creative-detail links are canonicalized to the exact advertiser breadcrumb profile before navigation; only the base `/advertiser/AR<digits>` path can be saved as a profile. Missing/ambiguous suggestions and ineffective clicks pause for review without losing SERP data or closing job tabs. **Quét dự án** keeps the profile open until explicit confirmation; invalid hosts or mismatched `AR<digits>` identities are rejected.
- Valentin: uses the live selector contract `#search-input`, `#regions`, `#hl`, `#gl`, `#place`, `#button-locate`, `#latitude`, `#longitude`, `#uule`, and `#button-search`. Native setters dispatch `input` and `change`. Exact-location mode requires fresh coordinate/UULE agreement; country-only mode explicitly removes location/UULE fields before search.
- Google Search: after the explicit Hi Auto start action, each document validates exactly `https://www.google.com/search` plus decoded `q`, `gl`, `hl`, `start`, inferred page and page limit before writing. Paid top/bottom blocks are saved in batches; organic results remain dropped evidence.
- Ads Transparency: starts only from a selected confirmed catcher. Profile save waits for the bounded DOM to settle; a labelled legal name wins, with a single exact-profile breadcrumb or non-creative level-one heading accepted as a provenance-bearing fallback. Ambiguous identities still require review. The bounded traversal gives discovered open shadow roots fair budget, preserves multiline profile text, and walks the complete same-root ancestor path for each direct creative anchor. A one-ID/one-iframe outer card wins over a nested evidence-only wrapper; multi-ID grids and whole-page text are excluded. Local semantic profile/region/total candidates beat global ancestors, while unresolved totals require review.
- Google ad iframe: `content/google-ad-frame.js` runs in child frames only and generates a fresh document identity locally for every child-document lifetime. For at most seven seconds/five changed messages it observes delayed body mutations with polling fallback and sends only changed content fingerprints. The cache is isolated by session/tab/profile/advertiser/frame/document identity and never lets an empty snapshot replace full content. Mapping is observed only when the canonical URL has one owning creative and one competing frame/document after revision collapse; raw/canonical twins, redirects, or ambiguity stay `unknown`.
- Portfolio collection: the helper does not scan when the Ads Transparency profile opens. The user first applies a date filter/Show more, then clicks **1 · Quét hiện trạng** to replace the snapshot with only the currently rendered creatives. **2 · Xác nhận & OCR** sends one immutable batch to Hi Auto. The backend downloads every original HTTPS image to the content-addressed disk cache first, then runs the PC's local Tesseract processes in parallel and stores a durable checkpoint. The Side Panel shows `download → local OCR → sync` counts live; it does not transport and OCR one image at a time. Screenshots are never accepted as project-domain evidence. Terminal job metadata and unreferenced cached assets are removed automatically after the retention window.
- Project inference: an observed landing/display URL wins; otherwise a domain explicitly read from the creative image by local OCR can identify the provider. Confirmed projects with a usable brand/domain are published to the Ads Discovery source and queued for Traffic. Traffic PASS is required before Trends, and Trends PASS is required before Coupon Discovery.
- SiteData Traffic: Auto SiteData reuses one real Chrome tab, fills one queued domain, clicks Search exactly once, waits for the matching `/traffic/<domain>` result, then reads Monthly Visits and paces the next domain. Closed tabs are reopened safely; timeouts and technical failures remain retryable and are never stored as zero traffic. The Panel keeps a live recent-results list and explicit pause/retry controls.
- Coupon Discovery: the Side Panel can enqueue one, ten, a selected batch, or the backend snapshot of all projects without coupon evidence, then runs the bounded Google/source adapters sequentially. Quick mode targets up to two codes; normal/deep target up to five. Google searches are paced, jobs/leases/checkpoints/provisional candidates are persisted by Hi Auto, and `chrome.storage.session` keeps executor state across service-worker suspension. CAPTCHA, login walls and per-origin permission prompts pause for the user and never auto-retry. Candidates remain `discovered` until the user selects and syncs them; syncing records unverified manual evidence and never marks a code verified.
- Coupon Harvester: enable it for the visible source tab from the Side Panel, then click Show/Reveal/Copy yourself. Parallel DOM/deep-DOM, trusted click-diff, clipboard, fetch/XHR, canvas, URL/new-tab and learned-rule layers collect codes automatically. Optional OCR uses bundled Tesseract assets locally with no CDN or upload. Captures are scored, deduplicated and stored in `chrome.storage.local`; review, copy, source links, JSON/CSV export, per-layer settings and picker-created domain rules are available in the Side Panel and extension Options. Login/checkout/payment/password pages suppress runtime interception.
- Keyword Planner: **Kiểm cầu → Chạy bằng Browser Helper** creates the existing durable demand batch, assigns each generated CSV to the visible Keyword Planner upload control, waits for historical-metrics results, tracks the exact Chrome download created for the active job, and asks Hi Auto to parse/reconcile that local file into the original batch. A job stops for login, CAPTCHA, missing controls, a changed result format, or manual download; held jobs resume only after the user asks. Temporary Planner tabs are reused between parts and closed after the queue is exhausted.
- Affiliate Application: **Dự án → Tìm chương trình (Google)** opens one tracked SERP and keeps the Side Panel visible while the user selects the correct Affiliate/Partner form. After profile selection, the helper scans every visible ordinary field (including open shadow roots), fills learned values, and watches multi-step DOM changes so the next step is scanned automatically. An open modal/popup is preferred over the background page; same-origin iframe fields are scanned recursively, cross-origin popup frames expose a one-click permission action and are scanned in their own frame, and a same-host child popup tab/window is adopted by the current job. Every unknown short/select/long field appears in the Panel; an answer entered there is learned in the selected Hi Auto profile and applied immediately. The **Sửa trường đã điền** section also shows every non-sensitive value used on the current form; saving a correction updates the profile, rebuilds the plan and refills that exact form control immediately. Address Line 2 defaults to `N/A`; dates accept only real date values; Security Question selects the first real option and uses `hidigi`. Password and Confirm Password receive the same extension-local candidate, then switch together to a fallback if the first is rejected. The Auto Fill panel always offers a blank password editor: saving a new value replaces the local custom password and refills both fields without revealing the previously stored value. Password values are never sent to Hi Auto, AI, logs, exports, or the handshake. OTP, CAPTCHA, file upload, legal consent and Submit remain manual.

The manifest grants `https://www.google.com/*` because creative iframes are not limited to `/search`; the SERP collector remains separately matched to top-level `/search*`. No background timer or automatic live collection exists.

## Manual live acceptance checklist

Automated tests and both verifiers use sanitized fixtures only. The project owner must manually:

1. Load the extension unpacked and connect a fresh session.
2. On Valentin, verify all ten selectors, visible `regions` plus `hl/gl`, native UI updates, geocode completion, matching latitude/longitude/UULE, and no search click for stale/mismatch/timeout cases.
3. Capture five Google pages and compare visible top/bottom paid blocks, organic exclusions, page parameters, and duplicate-attempt ledger.
4. Confirm two catcher domains, select catcher A, and verify the helper shows A before Ads Transparency opens.
5. Save an English or Vietnamese advertiser profile and compare URL advertiser ID, legal name, location, verification, payer, region, and the UI `ads/quảng cáo` total (not card position).
6. Inspect open-shadow-root cards and Google iframe creatives; confirm exact frame URL mappings and that uncertain mappings remain unknown.
7. Run a small bounded portfolio collection and compare reported total, ID/text completeness, unique cards, improvements, text/partial, exact/unknown mappings, duplicates, batches, truncated, and stop reason. Confirm a delayed iframe upgrades an existing card instead of creating a second creative.
8. Verify saving A creates no advertiser relation from catcher B and mismatched/missing source context is rejected.
9. Preview a coupon landing with social/navigation links before the merchant link; save once with no selection (merchant unknown), then explicitly select the intended merchant and verify affiliate parameters.
10. Export Discovery Bundle v1 and inspect attempt conservation/provenance. Confirm only explicitly reviewed results are synchronized into Hi Auto.

Fixture success does not prove current live DOM compatibility, shadow-root/component names, current advertiser identity, visible English/Vietnamese labels, load-more/scroll behavior, iframe navigation/availability, catalog completeness, CAPTCHA/rate-limit behavior, or present-day campaign state. Those remain manual live acceptance items.

## Coupon Discovery smoke test

1. Start Hi Auto on `127.0.0.1:8770` (or the approved Tailscale origin), sign in, and connect Browser Helper from the Ads Discovery page so a short-lived pairing token is issued.
2. Open the extension Side Panel and choose **Chạy dự án tiếp theo**. Use **Xếp 10 dự án**, a selected batch, or **Chạy tất cả**; run-all snapshots eligible projects in Hi Auto and still executes one project at a time.
3. Grant access only to each coupon-source origin when Chrome asks. Log in or solve CAPTCHA yourself when the Side Panel pauses, then choose **Tôi đã xử lý xong, chạy tiếp**.
4. Review the source link and confidence for each candidate. Select the desired codes and choose **Đồng bộ mã đã chọn về Hi Auto**. They are stored as discovered/unverified evidence.

## SiteData Traffic smoke test

1. Start a Traffic batch from Hi Auto and open the **Traffic** tab in the Side Panel. Confirm the current domain is shown but SiteData does not Search by itself.
2. Choose **Dán domain** in the Panel, confirm only the input is filled, then click **Search** on SiteData yourself.
3. Confirm the Panel reports OK with Monthly Visits, adds the row to **Kết quả live**, and prepares the next domain for another manual **Dán domain** click.
4. For a `no_data`, login, quota, Cloudflare or read-error row, verify **Quét lại** requeues it and **Bỏ** records a skip without blocking the other domains.

## Keyword Planner and affiliate-form smoke tests

1. In **Kiểm cầu**, click **Chạy bằng Browser Helper**, sign in to Google Ads if requested, and verify the Side Panel advances from CSV upload to result download. If the live DOM changed, perform the named manual step and click **Chạy tiếp / thử lại**. Confirm the resulting demand worklist is refreshed and the temporary tab closes after the final CSV part.
2. In **Dự án → Cần đăng ký link**, choose **Tìm chương trình (Google)**, select the correct result manually, select a profile in the Side Panel, then choose **Quét & điền form này**.
3. Open a modal/popup form and confirm background fields disappear from the plan while popup fields are scanned. For an embedded cross-origin form, choose **Cấp quyền và quét popup** once and verify the Panel switches to its fields; also verify a same-host child popup window remains attached to the current job. Then verify every unknown ordinary field appears in the Panel; saving an answer must fill that exact visible field immediately. Open **Sửa trường đã điền**, change a normal text field and a select/date field, then choose **Lưu sửa & điền lại**; the matching website control and profile must both contain the corrected value. Confirm Address Line 2, date-only birth date, Security Question/Answer, and the matching Password/Confirm Password pair. Enter a replacement in the blank password editor and choose **Lưu mật khẩu mới & điền lại**; both password fields must change while the old value remains hidden. Move to the next form step and verify automatic rescanning; use **Quét lại hiện trạng** only as a fallback. OTP, CAPTCHA, file upload, legal consent and Submit stay manual. Submit yourself, then choose **Tôi đã tự nộp đơn**.
